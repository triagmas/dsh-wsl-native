# DSH for WSL (`dsh-wsl-native`)

[English](README.md) · **Русский** · [简体中文](README.zh-CN.md)

**Цель: официальный DeepSeek Harness Desktop остаётся интерфейсом Windows, а обычный новый чат и выполнение задач по умолчанию идут в полноценном Linux Harness внутри WSL2.** Сейчас это **требование к доработке, а не готовая функция**: выбор между Windows/WSL ещё не означает автоматическую маршрутизацию. Подробности — в [WSL-first contract](docs/wsl-first.md).

Это независимый форк проекта [Han-1413141/dsh-wsl-native](https://github.com/Han-1413141/dsh-wsl-native) (MIT). Мы сохраняем исходную архитектуру, переводим реализацию на **строгий TypeScript/TSX**, поддерживаем локализацию и удобные режимы разрешений.

- **Версия:** пакет `dsh-wsl-native 0.8.0`, кандидат к выпуску.
- **Целевая версия Desktop:** `0.2.1-rc.5`.
- **Статус:** код и CI проверены, но полноценное испытание в настоящем Desktop для этого пакета **ещё не выполнено**.
- **Разработка:** [Draft PR #1](https://github.com/triagmas/dsh-wsl-native/pull/1); merge и публикация релиза не выполнялись.
- **Языки интерфейса плагина:** английский, русский, китайский (упрощённый).

## Возможности

Плагин позволяет работать в одном официальном окне Desktop с двумя полноценными средами:

- **Windows Harness:** существующие Windows-проекты, инструменты, PowerShell и диалоги.
- **Linux Harness в WSL2:** Linux Bash, файлы, зависимости, рабочие каталоги, плагины и диалоги, выполняемые непосредственно в Linux.

Можно выбрать существующий WSL-дистрибутив и папку проекта, запускать и повторно использовать Linux runtime, переключаться между Windows- и WSL-диалогами, восстанавливать соединение, переносить задания и применять штатные `wsl_native_*` инструменты для операций между системами.

**Это не новый Desktop, не замена Harness и не проект по созданию виртуальных машин.** Приложение остаётся официальным, плагин лишь дополняет его.

## Требования и установка

Нужны официальный DeepSeek Harness Desktop, существующая WSL2 Ubuntu/Linux и поддерживаемый Linux Node.js (22.19+ для 22.x либо 24+) с npm.

При разрешённой установке используется CLI, поставляемая вместе с Desktop:

~~~text
<Каталог установленного Desktop>\resources\runtime\cli\bin\dsh.cmd
~~~

Общая форма команды:

~~~powershell
& $dshDesktop plugin --profile desktop add $packagePath
~~~

До запуска необходимо проверить, куда указывает `DSH_HOME`, и полностью закрыть Desktop. **Не устанавливайте экспериментальный пакет в рабочий профиль без отдельного разрешения.** Инструкция для изолированного тестового профиля находится в [плане R04](docs/r04-isolated-test.md). Эта инструкция пока не является подтверждением успешно проведённого запуска.

## Работа с интерфейсом

После установки плагина в Desktop:

1. Откройте панель **Windows & WSL**.
2. Выберите установленный дистрибутив WSL, Linux-пользователя и каталог проекта.
3. Запустите или переподключите Linux Harness.
4. Открывайте WSL-диалоги в существующем окне и переключайтесь между ними и Windows-диалогами.
5. При необходимости настройте **Protected / Trusted / Full Access** и время действия разрешений.

Настройки разрешений плагина **не являются системной песочницей**: WSL interop и примонтированные Windows-диски могут обходить ограничения плагина. Не проверяйте разрушительные команды на реальных пользовательских файлах.

## Разработка и проверка

~~~bash
npm ci
npm run verify
npm pack
~~~

Команда `npm run verify` выполняет проверку TypeScript, ESLint, переводов, тестов, сборки и пакета. В CI предусмотрены Windows/Ubuntu и Node.js 22/24. Лимит браузерного модуля плагина — 262144 байта.

По последнему отчёту до обновления документации: **175 тестов, 173 PASS, 2 SKIP, 0 FAIL**. Реальная интеграционная проверка по-прежнему необходима.
